Expression conditions

Proposal: hazard and UCA conditions become small typed expressions. Conditions are grouped by indentation instead of parentheses — each group has a header in words (All of, Any of, Not) and a coloured vertical bar — and that same layout is used for reading, text editing, structured editing and trace verdicts.

1 · How a condition reads

Rendered everywhere (UCA context, hazard condition, tables, docx/xlsx). A group is a header in words plus a coloured vertical bar that spans its members; nesting is indentation. In an all-of list the members are joined by a quiet “and”, in an any-of list by “or”, so it reads as a sentence. No logic symbols.

The same, as text

all of: Train speed > 0 any of: all of: Door state = closed Platform side ≠ left Emergency brake = applied Gap − 2 × Speed < 5 m not: Door state = prev(Door state)

Layout is indentation, like YAML or Python: a line ending in all of: / any of: / not: opens a group; its members are the lines indented below it. not: followed by a single condition may stay on one line. and/or/∧/∨ are accepted as aliases and rewritten on blur.

2 · Editing

One representation, two editors. The text editor is the fast path (autocomplete on variable names, typed errors inline); the rows editor is today's builder, extended so each row holds one expression instead of fixed variable/op/value boxes. In the rows editor the group tag is a dropdown (All of / Any of / Not) and groups are added with + all of / + any of.

4 · In a trace

The scenario trace shows the context at the step where the action is sent, line by line in the same layout. Both sides of a comparison must have the same type (same named symbolic type, same unit). Errors are shown in the editor and as validation findings; a text-only project never sees any of this.

6 · Model and code impact

Model

  • Cond = All | Any | Not | Cmp | Time | Event | Text; Cmp {left, op, right} over Expr = Const | Var | Prev | Call | Bin. Replaces Condition + Group; no migration, examples regenerated.
  • Printer ↔ parser (model/expr.ts), the text layout above is its canonical output.
  • Evaluator stays three-valued, with a per-line verdict tree for traces.

Open points

  • Refinement: expand only substitutes comparisons of a refined variable with a constant; arithmetic over a refined variable is left as is and flagged info.
  • Args on control-action parameters could use the same expressions (delay ≤ 2 × timeout); proposal: yes, second step.
  • Quantifiers over instances: not in this step.
  • Phasing: (1) Expr + evaluator + printer, (2) text editor, (3) rows editor, (4) trace verdicts, (5) refinement / MCP.
